## First pass: the five Cs
- **Category:** A retrospective by two of the system's designers. It reviews 20 years of design and implementation decisions across the L4 microkernel family, from L3 to seL4, and reports which were "Retained", "Replaced", "Abandoned", "Added" or remain "Unresolved" (pp.133, 136–147). It reports a few measurements (Table 1, p.135; pp.137, 140, 146), but it is not an evaluation paper.
- **Context:** Liedtke's L4 papers [Liedtke 1993a, p.133; 1995, p.136] and the "microkernel minimality principle" (p.136); the early-1990s IPC cost problem [Condict et al. 1994; Chen and Bershad 1993] (p.133); EROS and capabilities (pp.135, 138); seL4 verification [Klein et al. 2009] (p.133) and WCET analysis [Blackham et al. 2011] (p.135); the multikernel [Baumann et al. 2009] (pp.133, 143).
- **Correctness:** The main assumption is that IPC latency counted in cycles can be compared across very different processors. The authors hedge this themselves: "as far as comparisons across vastly different ISAs and micro architectures have any validity" (p.147). Most "lessons" are argued from the authors' own experience rather than measured. The few numbers are partly taken from cited work (Warton 2005, Nourai 2005, Liedtke 1993a; pp.138, 144).
- **Contributions:** (1) A history and family tree of L4 kernels (Fig. 1, p.134; pp.133–135). (2) One-way IPC cost across eleven kernel and processor pairs from 1993 to 2013 (Table 1, p.135) and kernel sizes (Table 2, p.136). (3) A verdict on each original L4 design principle and implementation trick (Sections 3–4, pp.136–146). (4) The conclusion that "the most general principles behind L4, minimality (including running device drivers at user level) and a strong focus on performance, still remain relevant" (p.147).
- **Clarity:** Clearly written. Each subsection ends with a boxed verdict (e.g. "Abandoned: Long IPC.", p.138). The measurement method behind Table 1 is not described.

## Concepts
| Concept | What the paper says | Page |
|---|---|---|
| Microkernel minimality principle (new) | "A concept is tolerated inside the µ-kernel only if moving it outside the kernel, i.e. permitting competing implementations, would prevent the implementation of the system's required functionality" [Liedtke 1995]; "Retained" as the key design principle. | p.136 |
| Synchronous (rendezvous-style) IPC (new) | The original L4's "only communication, synchronisation, and signalling mechanism"; avoids kernel buffering; "Replaced" by synchronous IPC augmented with, or replaced by, asynchronous notification. | pp.136–137 |
| Asynchronous endpoint / notification (new) | A single-word notification field; a send ORs a bit mask into it, and the receiver blocks or polls; "similar to multiple binary semaphores allocated within a single word". | pp.136–137 |
| Virtual message registers (new) | A configurable set of 16–64 message registers, some physical and the rest in a pinned per-thread memory area. | p.137 |
| Long IPC (new) | Multi-buffer messages copied by the kernel through a temporary mapping window; "Abandoned" because of complexity and verification, with shared buffers used instead. | pp.137–138 |
| IPC endpoint (port-like) (new) | A kernel object that holds the queue of pending senders or receivers and is the message destination instead of a thread ID; no buffering. | p.138 |
| Clans and chiefs (new) | Kernel redirection of messages that cross a clan boundary to the clan's chief; supports confinement; "Abandoned". | p.139 |
| User-level device drivers / interrupts as IPC (new) | Drivers are user processes, and interrupts are "IPC messages, which the kernel sends to the driver"; "Retained". | p.139 |
| Recursive page mappings / mapping database (new) | Authority over frames comes from existing mappings, established through IPC (map, grant, unmap); needs a mapping database. | pp.140–141 |
| Untyped memory and retype (seL4 kernel memory model) (new) | All kernel memory is subject to capabilities; "Retyping is the only way to create objects in seL4"; capability derivation tree; called "seL4's main contribution to OS design". | pp.141–142 |
| Event-based (single-stack) kernel (new) | One kernel stack with continuations instead of one stack per thread; "Replaced: Process kernel by event kernel in seL4, OKL4 and NOVA". | p.144 |
| Lazy scheduling / Benno scheduling (new) | Lazy: blocked threads are left in the ready queue. Benno: the ready queue holds all runnable threads except the running one, which gives a bounded WCET. | pp.144–145 |
| Direct process switch (new) | On IPC the kernel switches straight to the partner thread on the caller's time slice; "a form of time-slice donation". | p.145 |
| Clustered multikernel (new) | A big-lock kernel across cores sharing an L2 cache, combined with a restricted multikernel (no memory migration between kernels). | p.143 |
| IPC fast path (new) | Hand-optimised common-case IPC code, once in assembler and in seL4 in C; it achieves 188 cycles on ARM11. | p.146 |
