## First pass: the five Cs
- **Category:** Implementation and evaluation report (a master's thesis issued as a technical report). It covers a language (Concurrent Smalltalk, CST), its compiler (Optimist II) and an operating system (Cosmos) for the Message-Driven Processor (MDP) and J-Machine. Measurements were taken on a simulator (pp. 108, 127).
- **Context:** The J-Machine and MDP [14, 16] (p. 2), built by Dally's group (p. ii). JOSS, Totty's earlier kernel, is the source of the BRAT and the object-migration protocol (p. 5). The first Optimist compiler [21] (p. 22). Related work: Smalltalk-80 and optimised Smalltalk (TS), Yokote and Tokoro's CONCURRENTSMALLTALK, and the actor languages Cantor and Acore (pp. 10–13).
- **Correctness:** Premise: "the routing time for a message sent from one end of even a large J-Machine to another is on the order of several microseconds. Operating system overhead on processing and dispatching that message of more than a few microseconds is not acceptable" (p. 2). Instruction counts are given as "rough estimates" (p. 102). They are cross-checked against runs on 4- and 16-node simulated J-Machines in MDPSim (pp. 108–109). The network-saturation limit is a first-order analytical model (p. 110).
- **Contributions:** Listed on p. 4: a redesign of CST; Optimist II (compiler and interpreter); Cosmos; CST runtime libraries; changes to MDPSim; "Modifications to the MDP architecture that make it more suitable for Concurrent Smalltalk." Measured results: a grain size of about 60 instructions, about 100–120 instructions per function call, and about 2 (internal memory) or about 4 (external DRAM) cycles per instruction (pp. 114, 127–128).
- **Clarity:** Clear and well structured, with message-format figures and per-routine instruction-count tables (Figs. 4-10 to 4-21, Tables 7-1 to 7-6). The scan is image-only, with no text layer. Appendix E (the compiler listing) was removed for space (p. 184).

## Concepts
| Concept | What the paper says | Page |
|---|---|---|
| new: message-driven processor | "The MDP is message-based. In its normal mode of operation, the MDP listens on the network for messages ... dispatches on the address given in the first word of the message"; "almost completely message-driven". | pp. 2, 176 |
| new: grain size | "the average amount of time a method executes before suspending", measured at about 60 instructions, which the author found "surprising; it was expected to be much lower". | abstract (PDF p. 5), p. 7 |
| new: operating system overhead | About 70% of active time is in the OS. "operating system overhead time overwhelms the execution time in Concurrent Smalltalk methods". | pp. 104, 50 |
| new: cfuture (context future) | "a local future which cannot be passed outside the function without being touched". It is implemented with the CFUT hardware tag, "using much less overhead than cboxes in CONCURRENTSMALLTALK". | pp. 8, 11, 178 |
| new: distributed object | "an object that can process many methods at the same time without any serialization bottlenecks other than those required by the algorithm". The OS routes group-name messages to constituents. | pp. 2, 20 |
| new: home node and object migration | Each object has a home node, which tracks its location; migration uses RequestObject, MigrateObject, UpdateHome and Unlock messages. | pp. 68–72 |
| new: criticality | A number limiting what a system call may do (e.g. "No message sends"). It was introduced because "almost all of its routines are non-reentrant". | p. 58 |
| new: reduction of method calls to function calls | A compiler optimisation that removes method dispatch and often inlines the call, "highly successful". | pp. 4, 49 |
| new: tail forwarding | A tail-forwarded call is "one call and no return", about 36 instructions against about 100. | pp. 104, 106 |
| new: parallelism control | "a parallel computer can fail if a program exhibiting too much parallelism is run on it". A queue-threshold switch to sequential evaluation was explored. | pp. 121–124 |
| new: fanout bottleneck | Serialising copies of immutable objects through their single home node. | p. 119 |

## Notes
- **Source read:** a scan of MIT AI Lab TR AITR-1321, the second edition (updated September 26, 1991) of the May 1989 S.M. thesis. Downloaded from DSpace@MIT (hdl 1721.1/7090) through the bitstream API and saved as `papers/P70.pdf` (246 PDF pages, image-only, no text layer). The DTIC copy (ADA259417) returned HTTP 403. The 1991 edition does not include "the newest changes" (hardware I/O, debugging aids, first-silicon workarounds) (p. 1).
- **Coverage (pass 2):** read in full: front matter, Ch. 1–2, Ch. 3 (pp. 22, 45–50), Ch. 4 (pp. 51–80, 84), Ch. 5 (p. 85), Ch. 6–9, Appendix A.1 (pp. 129–130), Appendix D (pp. 176–183). Not read: most of Ch. 3 (pp. 23–44), pp. 81–83 and 86–97, Appendices A.2–A.15, B, C and F, and the bibliography.
- **Criterion:** the screening proposal of I1 is confirmed by I1(a) (SEND/SUSPEND instructions, p. 183), I1(b) (hardware queues and dispatch, p. 179) and I1(c) (Cosmos inter-node services are message protocols, pp. 70–76). The full text may also meet I2: Ch. 7 evaluates performance on an architecture its author calls "message-driven" (p. 176), with simulated measurements and stated causes (pp. 101–114). I2 does not require silicon. No exclusion criterion found. X5: a university technical report and master's thesis. X8: this is not the same system and results as P71 (the 1988 Optimist compiler report) or P12; the overlap with P12 is limited to describing COSMOS and CST.
- **Hardware–language content (relevant to SQ9; the field is n/a under I1):** the author argues that MDP tags let the compiler skip type analysis at little cost (p. 11). He proposes ISA changes (MOVE from ID registers to memory, a corrected FIP after faults, larger queues and XLATE tables; for the shortage of tags, several XLATE tables or multi-word keys) and hardware register shadowing for fast context switches (p. 125). He also lists four ways to add floating point, from software emulation through fault handlers to an on-chip FPU or RAP chips (pp. 117–118).
- **Measurement basis:** every number in Ch. 7 comes from MDPSim (simulated) or from instruction counts (analytical), not from J-Machine silicon (pp. 102, 108). MDPSim "assumes that the MDPs are connected by crossbar network" (p. 121).
- **Criteria (gate 3c, 2026-10-12):** I1 and I2. The I2-only fields (*Hardware–language trade-off*, *Adoption factors*) are filled in the follow-up pass with the SQ files.
