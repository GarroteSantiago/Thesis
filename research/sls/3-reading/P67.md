## First pass: the five Cs
- **Category:** Description of a working experimental multicomputer, its hardware, node kernel, programming model and first-year experience, with a few application results (pp. 22, 28–31).
- **Context:** Shared-storage multiprocessors with a processor–storage switching network, compared with message-passing machines (Fig. 2, p. 24). Influences named are Sullivan and Brashkow's homogeneous machine [13], Hoare's CSP [4], Hewitt's actors [2], Martin's processing surfaces [10] and Kung's systolic algorithms [6]. The design comes from Lang's modelling and simulation [7] (p. 33). The same CACM issue has articles on RISC and the Manchester dataflow machine (pp. 25–26).
- **Correctness:** The premise is that internode communication "should scale well to very large numbers of nodes" (p. 23). The claim that message-passing machines are "simpler and more economical than shared-storage machines" is argued, not measured (p. 23). The performance claims rest on an overhead measure σ, given as a range across "many programs" without a per-program table (p. 31).
- **Contributions:** A 64-node binary 6-cube of Intel 8086/8087 nodes, in use since October 1983 (pp. 28–30). Each node runs a kernel copy that handles message queuing and routing and gives processes non-blocking send/receive (pp. 23–24, 30). Reported results: speedup and overhead on real scientific programs (p. 31) and reliability over 560,000 node-hours (p. 30). The paper says the node is "a hardware simulation" of a future single-chip node (pp. 22, 28).
- **Clarity:** Clear and readable magazine-style prose, with a worked N-body example and its C code (Figs. 3–5, pp. 25–27). There are no tables, and the performance data are given only in running text (p. 31).

## Notes
- **Source:** ACM publisher scan (12 pp., printed pp. 22–33), downloaded from an MIT 6.173 course reading page, https://web.mit.edu/6.173/www/currentsemester/readings/R01-cosmic-cube-seitz-1985.pdf, and saved as `research/papers/P67.pdf`. The ACM DL PDF returned 403 or a bot check, and OpenAlex and Semantic Scholar list only the ACM link. The scan carries a reader's hand underlining on p. 30, and the p. 22 footer prints "Volume 28 Number 2", an apparent scan or printing error; the other footers say Number 1.
- **Criterion:** the full text supports I1 through I1(c), not X3. The node processor (8086) has no message mechanism, and messages are not a hardware primitive (p. 24). But the kernel's own parts communicate by messages ("outer kernel ... processes that user processes communicate with by messages rather than by system calls", p. 30; kernel copies route messages between nodes, pp. 23–24), so the kernel does not fail I1(c). X3 therefore does not apply. This is a judgement on I1(c), since the inner kernel itself is reached by system calls (p. 30).
- **Possible I4 (for the gate):** the paper argues SQ-relevant points outside its I1 fields. On model equivalence: "shared-storage machines can easily simulate message-passing primitives, whereas message-passing machines do not efficiently support code and data sharing" (p. 23), and hybrids "with a message-passing approach to nonlocal storage references and cache coherence, may well prove to be the most attractive option" for intermediate sizes (p. 23). On what shapes programs: "the attention the programmer must give to blocking on lock variables is tedious and can create incorrect or unnecessary constraints on message and program sequencing" (p. 32), "programming has not turned out to be as difficult as we should have expected" (p. 31), and dataflow's side-effect-free semantics "appears to get in the way" of simulations (p. 26). These are designer statements, not measured.
- **Reading depth:** the whole article was read (second pass); no third pass, since there are no derivations or data tables to re-check.
