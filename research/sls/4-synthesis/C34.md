# C34: High-level-language computer architecture and the semantic gap

## Definition
Machines directed at executing particular high-level languages, usually justified as narrowing the "semantic gap" between programming and machine languages. Merges "high-level language computer (HLLC)", "HLL computer system (HLLCS)", "direct execution machine", "HLLESF", "HLLSSF / HLLPSF", "semantic gap" (two records), "transparent reversibility of compilation", "Lisp machine", "emulation machine", "CDR-coding", "generic instructions" and "high-level language uniprocessor".

## First found in
P15

## What the papers say, compared
- **The 1980 retrospective.** Ditzel and Patterson list "Reduce the semantic gap" among the common justifications without defining it (P280, p. 97), note that "only a handful" of HLLCs were built and none is commercial (P280, pp. 97–98), and expect direct execution machines not to "become viable" (P280, p. 100). They define a high-level-language computer system by its behaviour to the user, which "does not restrict the implementation to hardware or software" (P280, p. 100), and propose measuring support by the ratio of a fast unchecked system's time to the checked system's (HLLESF) (P280, p. 101).
- **Language machines built.** The Lisp machine was "specially microcoded to run Lisp" (P15, p. 12); the Dorado was "basically an emulation machine" for byte codes (P15, p. 14); Lisp Machine instructions are generic, typing operands at run time (P73, p. 484). The 432 is tested "as a high-level language uniprocessor" (P29, pp. 17, 23).
- **Judgements.** Ungar: earlier language machines "closely coupled the source language semantics to the hardware ... this approach has usually resulted in increased cost and poor performance" (P11, p. 14). The EROS authors use the term the other way: their kernel is fast partly because the "semantic gap" between its abstractions and the hardware is "minimal" (P77, p. 183).
- **Comparison.** The papers that judge the approach (P280, P11, P15) agree it did not pay; none of them discusses messages or objects as the raised interface (P280's record notes it never mentions messages).
