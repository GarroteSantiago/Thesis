# C28: Channel contracts and protocol rules

## Definition
Declared rules on which messages may flow on a channel and in what order, checked statically or at run time. Merges "channel usage rules" and "channel contract" (two records).

## First found in
P9

## What the papers say, compared
- **Checked at run time, in Go.** Go panics when a closed channel is closed again or sent to, and a nil channel blocks forever; breaking these rules is "one major reason" for the concurrency bugs studied (P9, pp. 2–3, 12).
- **Checked statically, in Sing#.** Singularity channels have "formal typing and protocol specifications": declared messages and a state machine for the protocol (P49, pp. 49–50); Helios inherits the contracts (P45, p. 5).
- **Comparison.** One side has defect counts but only run-time rules (P9); the other has static contracts but no defect study among the papers read.
