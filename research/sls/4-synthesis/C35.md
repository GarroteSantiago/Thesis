# C35: Language support moved from hardware to the compiler

## Definition
Compilation and runtime techniques that obtain on simpler hardware the performance special hardware promised. Merges "compiler-protected intra-module call", "in-line caching", "compilation to a low-level instruction set", "Smalltalk On A RISC (SOAR)", "compiling all methods", "bytecodes as the semantic definition" (compiler side), "in-line method cache", "sufficiently smart compiler", "reduction of method calls to function calls" and "Threaded Abstract Machine".

## First found in
P10

## What the papers say, compared
- **SOAR's measurements.** Compiling Smalltalk to a low-level instruction set instead of bytecodes gives "an approximate doubling in speed" for about 500 KB more memory (P11, pp. 34–35, 68); in-line caching replaces lookup hardware, and instantaneous lookup hardware would gain at most 23% (P11, pp. 13, 45–47, 68). In-line caches work because "96% of the time the method invoked does not change" (P261, p. 8). Several SOAR features "could easily be performed by the compiler at marginal increased time and space costs" (1–3%), but software tag tests would cost an estimated 26% in speed (P261, pp. 6–7, 10).
- **The 432's compiler.** Moving intra-module call protection from hardware to the compiler would save up to 20.5% on Dhrystone (P10, pp. 315–316).
- **Lisp.** The "sufficiently smart compiler" was a recurring hope for stock hardware (P15, p. 23); stock-hardware Lisps did match Lisp machines on garbage collection (P15, pp. 34–35).
- **Message machines.** On the J-Machine, reducing method calls to function calls was "highly successful" (P70, pp. 4, 49). The Threaded Abstract Machine runs the message-driven model in compiler-managed software handlers, which "does not necessarily result in lower performance than a direct hardware implementation" (P33, p. 437).
- **Disagreement.** Ditzel and Patterson say special hardware does not "greatly" simplify compilers (P280, p. 98), while the J-Machine's hardware tags free the compiler from type analysis (P70, p. 11), and SOAR's hardware "in the main simplified" its compiler (P261, p. 10). The papers agree compilers recover most of the gain and disagree on whether tags still pay.
