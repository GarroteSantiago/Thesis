# C32: Message send and procedure call as one mechanism

## Definition
A message send and a procedure or method call are carried by the same machinery, or shown to be interchangeable. Merges "refinement (Message object)", "domain refinement", "context object", "generic operation / sending a message", "method", "flavor", "instance", "combined method", "select-method", "entity", "message-receiving stream", "Flavors", "actors and closures are the same concept", "selector-object dispatch" and "tail forwarding".

## First found in
P10

## What the papers say, compared
- **The 432 passes call parameters in a message.** A procedure call puts parameters in a Message object that is a refinement of the caller's context, saving the caller a cache miss but costing the callee 148 cycles to traverse (P10, pp. 306–307, 323); contexts are built by hardware (P72, pp. 169, 172–173).
- **The Lisp Machine makes a send a call.** "performing a generic operation is called sending a message"; microcode binds self and calls the flavor's select-method, and "no new features are added to Lisp for message sending" (P73, pp. 283–285, 309); Flavors is "a ... message-passing system" (P15, p. 26).
- **Equivalence, with exceptions.** Sussman and Steele found "the codes in apply for function application and for actor invocation were identical", so "actors and closures were the same concept"; Hewitt's exceptions were cells (state) and synchronizers (exclusive access) (P15, p. 17); the lambda calculus captures actors "excepting only side effects and synchronization" (P15, p. 63).
- **SOAR has no send instruction.** A send compiles to a call plus software lookup with an in-line cache (P11, pp. 37, 46–47; P261, p. 8).
- **A message machine whose compiler turns sends into calls.** On the MDP a method invocation is a message to its first argument, dispatched through a selector object, but known types bypass it with a direct call (P12, pp. 20–21); tail forwarding makes a call "one call and no return" (P70, pp. 104, 106).
- **Comparison.** Where the receiver is in the same address space, every system read treats send as a call; the equivalence fails exactly on state and synchronisation (P15), which is what separate message machines add.
