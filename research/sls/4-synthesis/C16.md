# C16: Multikernel: the operating system as a distributed system of cores

## Definition
One kernel instance per core or per memory domain, sharing no kernel state, with all coordination between cores by explicit messages. Merges "multikernel", "explicit inter-core communication", "hardware-neutral OS structure", "CPU driver", "monitor", "dispatcher", "system knowledge base", "spectrum of sharing and locking", "satellite kernel", "NUMA as a shared-nothing multiprocessor", "affinity", "two-phase compilation", "factored operating system", "space multiplexing replaces time multiplexing", "fleet", "fos client", "OS-application locality aliasing" and "clustered multikernel".

## First found in
P8

## What the papers say, compared
- **Three designs from 2009, three motivations.** Barrelfish structures the OS "as a distributed system of cores that communicate using messages and share no memory", placing itself at the far end of a spectrum from shared and locked to fully replicated state (P8, p. 5); it argues from coherence costs and hardware diversity (P8, pp. 3–5). Helios runs a satellite microkernel per NUMA domain and per programmable device of another instruction set, and places processes by affinity hints at start (P45, pp. 1–8). fos factors the OS into services run by fleets of servers on their own cores, so "Scheduling becomes a layout problem not a time multiplexing problem" (P102, pp. 5–6), arguing from cache interference between OS and applications (P102, p. 4).
- **A kernel line that went part of the way.** L4's clustered multikernel uses a big-lock kernel across cores that share an L2 cache, and a restricted multikernel between clusters with "no memory migration" (P48, p. 143).
- **None is free of shared memory.** Barrelfish's channels and applications share memory (P8, pp. 5, 11); Helios carries remote messages over shared FIFOs (P45, pp. 6–7); fos may use shared memory as transport and for small applications (P102, pp. 2, 5).
- **Costs of not sharing.** Helios processes may not span domains, which "could hamper large, multi-threaded processes" (P45, pp. 5, 13); L4's restricted multikernel gives up memory migration (P48, p. 143); Barrelfish's split between CPU driver and monitors costs "several thousand cycles" per OS call (P8, pp. 11–12).
- **Evidence differs.** Barrelfish is measured up to 32 cores, but its authors warn against "quantitative conclusions from our large-scale benchmarks" (P8, p. 16); Helios is measured on 4 cores and an I/O card (P45, pp. 9–11); fos is a design under development (P102, p. 8).
