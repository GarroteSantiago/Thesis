# C23: Invocation as the only system call

## Definition
The kernel offers one operation, sending a message by invoking a capability or port, and every other action is reached through it. Merges "key invocation", "domain", "capability invocation as the only system call", "actor transmission" and the 432's "message port" as an instruction-set operation.

## First found in
P53

## What the papers say, compared
- **Two capability kernels make it total.** KeyKOS relies "totally" on capabilities, "without any other mechanisms"; "Sending a message is sometimes referred to as key invocation", by call, fork or return (P53, pp. 3, 7). In EROS "capability invocation is the only 'system call' implemented by the kernel", so "all actions taken by a process are implicitly access checked" (P77, pp. 173–174).
- **A processor makes it partial.** The 432 has instructions that send messages to and receive messages from port objects, but procedure calls, scalar operations and faults are not messages (P72, pp. 159, 162, 171).
- **The actor version is a claim.** Hewitt and Smith's "universal communication mechanism", quoted by Steele and Gabriel, generalises Smalltalk's and Simula's messages (P15, pp. 61–62).
- **Where each kernel stops.** KeyKOS keeps the trap instruction for binary compatibility and treats loads and stores as "isomorphic to read and write messages on the page key" (P53, pp. 9–11). EROS has a per-process mode bit that disables capability invocation "For emulation of other operating systems", and keeps loads and stores (P77, p. 173). Mach started with one message call and added others (P77, p. 182).
- **Comparison.** The papers agree one invocation can carry all kernel services; both kernels read still keep memory access and a compatibility trap outside it.
