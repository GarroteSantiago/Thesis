# C11: One channel abstraction over several transports

## Definition
One message interface for the program, whatever carries the message (same core, another core, another kernel or a device of another instruction set); the transport is chosen per channel. Merges "late binding of protocol and transport" and "remote message passing (RMP) vs local message passing (LMP)".

## First found in
P8

## What the papers say, compared
- **Barrelfish binds transport late.** Protocol and transport are chosen at run time to fit the hardware or workload; all transports sit behind a common interface with marshalling generated by a stub compiler (P8, pp. 6, 10). Same-core LRPC and inter-core URPC are both offered (P8, pp. 8–10).
- **Helios keeps the interface and changes the cost.** Local message passing is zero-copy within a kernel; remote message passing marshals and copies once between kernels, beneath the same IPC abstraction (P45, pp. 3, 6–7). A local send takes about 10 µs and a remote one about 11–128 µs by size, read off its Fig. 5 (P45, p. 10).
- **fos leaves the transport open** ("via on-chip networks or shared memory") and turns system calls into messages through a proxy library (P102, pp. 5–8).
- **Comparison.** All three keep one interface; Helios measures the cost difference, Barrelfish does not claim that swapping transports is interposition (P8, pp. 6, 10), and Helios is the one that uses it to move a component without changing the program (C25).
