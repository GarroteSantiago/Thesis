# C22: Capabilities

## Definition
Unforgeable references that both name an object and carry the rights to use it. Merges "protected pointer (capability, Access Descriptor)", "access descriptor (AD)", "level number (lifetime check)", "guarded pointers", "key (capability)", "principle of least privilege", "capability", "protection domain", "weak access right" and "IPC capabilities".

## First found in
P10

## What the papers say, compared
- **In hardware and microcode.** On the 432 only microcode creates and changes Access Descriptors, which carry the bearer's rights; every reference is checked for rights and bounds (P10, pp. 302–306). ADs are 32 bits and "can be freely copied", and the hardware refuses to store an AD where it would outlive its object (P72, pp. 161, 165, 181–182). The M-Machine uses guarded pointers as a light-weight capability system (P66, pp. 2–3).
- **In software kernels on ordinary processors.** In KeyKOS "Every object in the system is exclusively referred to by one or more associated keys", and objects have "no intrinsic authority" beyond their keys (P53, pp. 3–4). EROS defines a capability as "an unforgeable pair made up of an object identifier and a set of authorized operations"; a weak capability gives transitive read-only access (P77, pp. 171, 174). seL4 puts all kernel objects and memory under capabilities (P48, pp. 137–142); Barrelfish models its capabilities on seL4's (P8, p. 10). Minix 3 restricts which IPC primitives and destinations a process may use with bitmaps, called IPC capabilities (P49, p. 48).
- **As a property of messages.** Hewitt and Smith, quoted, claim "Every actor transmission is in effect an inter-domain call efficiently providing an intrinsic protection on actor machines" (P15, p. 62); no system is given.
- **Cost.** On the 432 a byte access "potentially requires four references", which Levy calls comparable to conventional virtual memory and reduced by caches (P72, pp. 166, 185–186). The CAP computer's language-grain capabilities caused "higher-frequency dereferencing of capabilities than the hardware can effectively support", while "capability systems can perform well without resorting to specialized hardware assists" (P77, p. 182).
- **Comparison.** The papers agree on what a capability is; they disagree on where to check it. The software kernels (KeyKOS, EROS, seL4) report good performance on commodity hardware; the hardware designs (432, CAP) report costs, but only Levy's is attributed to the addressing itself and none is measured here (C31).
