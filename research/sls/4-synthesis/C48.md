# C48: Is message passing less error-prone?

## Definition
The belief, tested empirically, that communicating by messages causes fewer concurrency bugs than sharing memory. Merges "cause dimension (shared memory vs. message passing)" and "message passing is less error-prone (common belief, refuted for blocking bugs)".

## First found in
P9

## What the papers say, compared
- **Tested in Go.** "Contrary to the common belief", message passing causes 49 of 85 blocking bugs (about 58%) although shared-memory primitives are used more; shared memory causes 69 of 86 non-blocking bugs (about 80%), so "When used correctly, message passing can be less prone to non-blocking bugs" (P9, pp. 2, 5–6, 9–12). The ratio divides bug counts by static counts of primitive use, not by how often each runs (P9 record, Correctness; pp. 4, 6).
- **Scope limit.** Go programs mix both models; none is a system where each piece of state has one owner (P9, pp. 2–3).
- **The shared-memory side, without a comparison.** Order intentions are hard to express or enforce with locks or transactional memory (P5, p. 338); P5 has no message-passing counts.
- **An argument.** Shared data has "correctness and performance pitfalls" (P8, p. 4).
- **Comparison.** The only direct test refutes the belief for blocking bugs and supports it for non-blocking ones, within a language that does not enforce ownership; evidence for systems that do is absent from the papers read (P78, P79 unread).
