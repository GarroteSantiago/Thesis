# C31: Object-based processor and object addressing

## Definition
A processor in which all information is held in protected objects, reached through capabilities and object tables, with a check on every reference. Merges "object model", "two-level addressing", "entered environment and object qualification", "transparent multiprocessing", "object-based microprocessor", "object descriptor / object table / Object Table Directory", "type manager", "type control object and rights amplification", "type definition object", "object-oriented architecture with software-transparent multiprocessing and fault tolerance", "segmentation structure" and "instruction set design".

## First found in
P10

## What the papers say, compared
- **What it is.** In the 432 all information is encapsulated in protected objects (P10, p. 297); "Everything in the Intel 432 is an object", the "first object-based microprocessor" (P72, pp. 159, 184). Access Descriptors lead through an Object Table Directory and object tables to physical addresses, separating location from rights (P10, pp. 304–305; P72, pp. 163–165); an object must be "entered" and "qualified" before use (P10, pp. 303–304). The object model lets the same software run on a variable number of processors (P10, p. 297). Witten and Cleary's abstract places the 432's novelty in its "sophisticated segmentation structure" and instruction set (P74, abstract; abstract only).
- **Cost, as each evaluator frames it.** Levy says a byte access "potentially requires four references", an overhead "comparable to the overhead required on any conventional virtual memory system", reduced by caches (P72, pp. 166, 185–186). Colwell et al. put the inherent cost of the 432's object orientation at 2–3x as a residual, and say flushing the data-segment cache on every protected call could be fixed by an AD cache "without violating any of the fundamental principles of object orientation" (P10, pp. 325, 336–337). Hansen et al. ask "how much performance is degraded because of the object-oriented architecture" but do not isolate it (P29, pp. 17–18, 23).
- **Comparison.** All three evaluators are independent of the designers; they agree the 432 was slow and disagree on how much is due to object addressing (P72: like virtual memory; P10: 2–3x residual; P29: not separable).
