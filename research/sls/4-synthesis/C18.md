# C18: Central components in systems of message-passing parts

## Definition
Functions that stay with one coordinator (a node, a kernel, a server or a root object) in a system otherwise made of parts that share no state. Merges "coordinator kernel", "centralised namespace", "meter" (prime meter), "space bank" (master), "notional lock / lock server", "distributed object" and "fanout bottleneck".

## First found in
P45

## What the papers say, compared
- **Naming.** Helios keeps its namespace in the coordinator kernel "for the sake of simplicity", since it is used only at process start and connection setup (P45, pp. 5–6); Minix 3 and Singularity each have one name server (P49, pp. 47–50).
- **Resources.** KeyKOS subdivides CPU time from one kernel "prime meter" and storage from a master space bank, though "multiple master space banks" are possible (P53, pp. 4, 6); EROS's single space bank "owns all system storage" (P77, p. 179). The J-Machine kernel "serializes the allocation of distributed objects at one node because of the need to give each distributed object a unique ID" (P70, p. 120).
- **Failure handling.** KeyKOS checkpoints the whole system while "all processes are briefly suspended" (P53, pp. 4, 8); EROS halts all processes for a whole-machine snapshot, under 50 ms for 256 MB (P77, p. 174).
- **Atomicity and scheduling.** fos still needs "synchronization points", met by a lock server or a core acting as a transaction server, and warns "the cost of software-based lock management may dwarf the performance wins" (P102, pp. 5, 8). L4's designers think "a global scheduler makes more sense" on embedded multicores with cheap migration (P48, p. 138).
- **Interrupts.** Helios steers all interrupts to the coordinator, which "restricts the location of device drivers" (P45, pp. 6, 13).
- **Named costs.** Bottlenecks at a home node (P70, p. 119) or a gateway thread (P48, p. 143), and restricted placement (P45, p. 13); none is measured.
- **Comparison.** Reasons for keeping a centre: simplicity (P45), uniqueness of names (P70), a consistent snapshot (P53, P77), atomicity (P102) and cheap migration (P48). No paper read shows a decentralised version of these functions working with a measured cost, apart from Barrelfish's capability scheme, which its authors regret (C17).
