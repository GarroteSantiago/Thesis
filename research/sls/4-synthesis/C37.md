# C37: Hardware type tags and traps

## Definition
Data words carry type tags checked in parallel with the operation; a mismatch traps to software. Merges "tags trap bad guesses", "integer tags and traps" and "generic instructions".

## First found in
P11

## What the papers say, compared
- **SOAR guesses and traps.** "SOAR assumes that the operands are integers ... simultaneously checking the tags", trapping if wrong (P11, p. 31); on a non-integer "the hardware will trap and transfer to a handler that will look up the correct method" (P261, p. 6). Doing the tests in software would cost an estimated 26% in speed and 15% in image size (P261, pp. 6–7).
- **The MDP keeps tags for synchronisation and typing.** Tags make the no-fault case faster than "test and branch instructions" (P12, p. 7); traps on type errors serve dynamic typing and uniform local and remote access (P69, pp. 189, 194). Tags free the compiler from type analysis: "even if Optimist II cannot determine the type of some expression, performance does not suffer too much" (P70, p. 11), but there are only 16 tags (P70, p. 125).
- **The Lisp Machine makes every instruction generic,** which brings "data dependencies that can have major effects on the speed of execution" (P73, p. 484).
- **Comparison.** Three independent designs keep tags; the only quantified benefit is SOAR's estimate (P261), and no paper read weighs it against a compiler with type inference.
