# C2: Handler address carried in the message

## Definition
Each message names, in its first word, the code the receiver runs when it arrives, so dispatch needs no lookup at the receiver. Merges "Active Messages", "dispatch instruction pointer (DIP)" and the MDP's header-as-instruction-pointer.

## First found in
P33

## What the papers say, compared
- **The same idea appears in software and in hardware.** Active Messages put the address of a user-level handler at the head of each message; the handler runs to completion on arrival (P33, p. 431). On the MDP the instruction pointer comes from the message header (P65, p. 2), and the processor "dispatches on the address given in the first word of the message" (P70, p. 2); the 1987 design encodes it as EXECUTE with a priority and an opcode (P69, p. 191). The M-Machine's first word is a DIP that the handler jumps to (P66, p. 7).
- **Where it runs differs.** Active Messages are a convention on conventional nodes (nCUBE/2, CM-5), carried by a user-level layer over a network interface (P33, pp. 431–433); the MDP and the M-Machine dispatch in hardware (P65, p. 2; P66, p. 7).
- **Protection is handled differently, or not at all.** The M-Machine restricts which DIPs a program may use (P66, pp. 3, 7). On the nCUBE/2 the kernel checks the destination and length of each send (P33, p. 433). On the 1987 MDP, READ and WRITE messages from any sender reach physical memory (P69, pp. 189–194). Whether a message that names its own handler can be made safe without a check on every message is not settled by these papers.
