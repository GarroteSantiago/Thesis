# C43: Shared memory built on messages

## Definition
A shared address space or coherent memory implemented by messages between nodes, kernels or caches. Merges "global virtual address space over message passing", "unifying shared memory and message passing", "shared memory layered on message passing", "incremental parallelization", "block status bits" (use), "coherence messages implement shared memory" and Split-C's PUT/GET.

## First found in
P12

## What the papers say, compared
- **Measured on two message machines.** The M-Machine layers "a coherent shared memory system ... on the message-passing substrate" in trap handlers, so unmodified sequential programs run and are parallelised step by step; a remote read costs 138 cycles against 3 for a local cache hit, a remote write 74 against 2 (simulated) (P66, pp. 1–2, 6, 8–10). On the J-Machine a remote read is a three-word request message costing 60 cycles to a neighbour and 98 across 512 nodes (P65, pp. 3, 11).
- **Claimed without measurement.** The MDP can "build a shared memory model that gives the application programmer a single, shared address space" (P12, pp. 3, 5); it is "an experiment in unifying shared-memory and message-passing parallel computers" (P64, p. 12) and offers "many of the advantages of both" (P69, p. 196).
- **In software layers and kernels.** Split-C gives a "familiar shared-memory style" of PUT and GET over Active Messages (P33, p. 434). Barrelfish builds a shared virtual address space from replicated page tables kept consistent by messages (P8, p. 11). KeyNIX builds a binary-compatible UNIX on KeyKOS's messages, at a cost for trivial calls (getpid at 0.4 of Mach 2.5) (P53, pp. 10–11, 14–15).
- **Every coherent chip already does it.** Coherence is carried by point-to-point request, forward, invalidation and acknowledgement messages between cache controllers (P22, pp. 2–3).
- **Comparison.** Where measured, remote shared access costs 20–50 times a local hit; properties kept: transparency (P66), failure isolation per process (P53); lost: encapsulation, since any program can load and store remote data (P66, record's inference). P22's point reframes the question: the choice is which level exposes the messages, not whether they exist.
