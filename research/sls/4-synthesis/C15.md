# C15: Non-message paths added later

## Definition
Mechanisms that are not message sends, added to a system that began message-based, usually for performance, convenience or compatibility. Merges "reintegration into the kernel", "long IPC" (abandoned for shared buffers), "selector-object dispatch" (bypass), "reduction of method calls to function calls" and "criticality".

## First found in
P12

## What the papers say, compared
- **Kernels moved servers back in, or added calls.** Chorus's "supervisor actors" and Mach's "kernel-loaded tasks" "reintegrated the most critical servers and drivers into the kernel", which "weakens the microkernel approach" (P46, p. 73). Mach "originally started with a single mach_msg system call, additional system calls were later added for performance" (P77, p. 182).
- **L4 added non-message primitives beside IPC.** Asynchronous notifications, counting semaphores and virtual IRQs were added, and long IPC was abandoned for shared buffers because it was complex, "rarely used" and hard to verify (P48, pp. 136–139).
- **An emulated system kept a shared table.** KeyNIX, a UNIX built on KeyKOS's messages, shares the process and open-file tables in a segment, which its designers call "the primary impediment to distribution" (P53, pp. 11, 17).
- **Compilers turn sends into calls.** On the MDP, a Concurrent Smalltalk call whose receiver type is known "is optimized directly to the correct function invocation" (P12, p. 20); the "reduction of method calls to function calls" was "added and found to be highly successful" (P70, pp. 4, 49). The kernel also has system calls that may send no messages, because "almost all of its routines are non-reentrant" (P70, p. 58).
- **Allowed by design, not built.** The multikernel model allows a replica shared under spinlocks by closely coupled cores, which the authors call "a next step" (P8, pp. 7, 18).
- **Comparison.** Reasons given: performance (P46, P77, P12, P70), simplicity and verification (P48), compatibility with an existing system (P53). In every case the message interface stayed and the new path went beside or below it.
