# C36: Architect's trap

## Definition
Specialised hardware features that speed one operation and add design time without improving overall performance.

## First found in
P11

## What the papers say, compared
- **Named by Ungar.** Four of SOAR's specialised features were "mistakes"; the garbage-collection hardware "probably did not speed up SOAR" (P11, pp. 70, 72, 126).
- **The same lesson in 1980.** On SYMBOL, adding hardware did not make the system "run proportionally faster" (P280, p. 102); HLLC designers "ignored the view of the total system" (P280, p. 103), and hardware is costly to debug (P280, p. 99).
- **In the 432.** Bit-aligned instructions did not make code much smaller than VAX or 68000 code, and the value of a complete instruction set is doubted because high-level-language users never see it (P10, pp. 298–299, 301).
- **In message-driven hardware.** Its support is "partly counter-productive" for processing performance (P33, p. 435).
- **Comparison.** The papers agree across language machines; P33 extends the warning to message-driven processors, the closest case to this thesis.
