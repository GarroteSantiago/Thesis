# C7: Messages and communication in registers

## Definition
Message contents, the head of a message queue, or communication between execution units mapped onto processor registers, so a send or receive avoids memory. Merges "virtual message registers", "register-mapped message queue", "H-Thread" (register communication), "priority register sets" and "memory-based architecture for fast context switches".

## First found in
P48

## What the papers say, compared
- **Hardware designs map the queue onto registers.** The M-Machine makes the head of the message queue a register, so messages are not copied to or from memory (P66, pp. 7–8); its H-threads also communicate and synchronise "via registers" (P66, pp. 3–4). The Active Messages authors propose message registers, PC injection and user-level interrupts, and expect such support to cut handling to "a handful of instructions, but not to one" (P33, pp. 438–439).
- **A kernel does the same in software.** L4 uses 16–64 virtual message registers, some physical and the rest in pinned memory (P48, p. 137); in-register transfer is 10% faster than passing on the kernel stack on ARM11 and 4% on Cortex A9 (P48, pp. 137–138).
- **The MDP chose few registers on purpose.** It keeps one small register set per priority so a low-priority message is preempted "without saving state", and a memory-based instruction set so a context switches in under 10 cycles (P69, pp. 189, 191, 196). Its evaluators later name the "paucity of registers" as a limit (P65, p. 11).
- **The 432 had none.** It is a memory-to-memory machine with no data registers, for chip size and faster process swaps (P10, pp. 302, 318).
- **Tension.** Registers make sends cheap, but message-driven handlers are too short to use many registers (C1, C38).
