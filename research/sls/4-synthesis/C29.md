# C29: Failure isolation and recovery

## Definition
How a message-based system contains a failed part and restores it. Merges "fault isolation", "reincarnation server (self-healing)", "shadow driver" and "checkpoint with consistency check".

## First found in
P49

## What the papers say, compared
- **Per component.** Minix 3's reincarnation server is the parent of all servers and drivers and restarts one that crashes or "fails to respond to the periodic pings" (P49, p. 48); Nooks' shadow drivers log and replay a driver's communication after a restart (P49, p. 46). The motivation: in current kernels "Every single one of the millions of lines of kernel code can overwrite key data structures" (P49, pp. 44–45).
- **Whole machine.** KeyKOS takes system-wide checkpoints with all processes briefly suspended (P53, pp. 4, 8); EROS checks each whole-machine snapshot for consistency before commit, since "Once committed, an inconsistent checkpoint lives forever" (P77, p. 174).
- **None.** In Barrelfish "the complete system is a failure unit" (P8, p. 17).
- **Comparison.** Isolation by messages makes per-component restart possible (Minix 3), but the two persistent capability systems recover centrally (C18), and the multikernel does not attempt it.
