# C42: The base outside a self-defining system

## Definition
The level that a system written in its own terms still rests on and does not express in those terms: microcode subprimitives, a privileged kernel, a hand-built initial image. Merges "CPU driver" (as the base), "subprimitive", "no special privileges", "type manager" (hardware part), "bytecodes as the semantic definition", "constructor" (initial image) and "criticality".

## First found in
P8

## What the papers say, compared
- **Language machines.** "Everything on the Lisp Machine is written in Lisp, including all system programs", but subprimitives are "hand-coded in microcode", "cannot do full checking", and misused "can destroy the environment" (P73, pp. 1, 172). On the 3600 the OS, editor, compiler and collector were all Zetalisp, on a base "specially microcoded to run Lisp" (P15, pp. 12, 26); a new dialect can be bootstrapped inside a host providing "primitive operations such as arithmetic and I/O" (P15, p. 65). For SOAR "the virtual machine is the semantic definition of the language" (P261, p. 2).
- **Object processors.** On the 432, addressing, rights checks, IPC and scheduling stay in microcode and hardware, outside the object model, and that base fills chips (P10, pp. 298–299, 302, 305, 316). Programmer-defined type managers use mechanisms "identical" to the system's, yet hardware-defined operations remain (P72, pp. 173, 184–185).
- **Message machines.** On the MDP only EXECUTE is hard-wired and every other message is ROM code a user can redefine (P69, p. 191); but the kernel above is "hand-optimized assembly language" and the runtime is assembly because it implements "functionality that cannot be easily expressed in Concurrent Smalltalk" (P70, pp. 51–52).
- **Kernels.** Barrelfish's CPU driver, in C and assembly, lies outside the message model (P8, p. 8); L4 is written in assembler, C and C++, not in its own messages (P48, pp. 142–147); Singularity is "almost entirely in Sing#" except a trusted part (P49, pp. 49–50); EROS defines allocation and process construction in its own processes, but the kernel and "the hand-constructed initial system image" stay outside (P77, pp. 179–180).
- **Comparison.** Every system read keeps a base; its size ranges from one hard-wired message (P69) to large microcode (P10, P73). Only the 432 papers state what the base costs (chip space), and only the Lisp Machine manual states what it prevents (full checking).
