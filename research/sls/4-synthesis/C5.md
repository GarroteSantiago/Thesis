# C5: Presence tags and futures

## Definition
Memory words tagged as "not yet computed"; reading one traps and suspends the task until a value is written, which synchronises on data arrival without locks. Merges "presence tags / futures (FUT, CFUT)", "c-future / future tags", "futures via tags" and "cfuture (context future)".

## First found in
P12

## What the papers say, compared
- **All MDP papers keep the mechanism.** The 1987 design tags a reply target as a "context future" (P69, pp. 190, 194–195); later papers distinguish c-futures, cheaper and local, from copyable futures (P64, p. 12; P12, pp. 6–7; P65, pp. 2, 5). The designers' reason: "it is natural to associate the synchronization tag with the data" (P65, p. 2).
- **Cheap to use, costly to fault.** In Concurrent Smalltalk the CFUT tag gives futures "using much less overhead than cboxes" (P70, pp. 8, 11, 178), but saving and restoring context, "especially in the CFUT fault handler", is a named cost (P70, p. 114).
- **Other machines use a simpler bit.** The M-Machine has one synchronization bit per memory word with atomic loads and stores (P66, p. 3). None of these papers compares the two designs.
