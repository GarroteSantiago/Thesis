# C19: User-level resource allocation

## Definition
Memory and other resources are allocated by user-level servers through kernel mechanisms (mappings, capabilities to untyped memory, space banks), not by policy inside the kernel. Merges "external pager", "recursive address spaces: grant, map, demap", "recursive page mappings / mapping database", "Untyped memory and retype", "space bank" (two records) and "meter".

## First found in
P46

## What the papers say, compared
- **L4's path.** Mach's external pager, which forwards page faults to user-level tasks, was "the first conceptual breakthrough toward real microkernels" (P46, p. 71). L4 builds address spaces outside the kernel by grant, map and demap, with coexisting memory servers that must "cooperate" (P46, pp. 75–76). This needed a mapping database, and seL4 replaced it with Untyped memory and retype, "seL4's main contribution to OS design": "by limiting access to Untyped memory, a system can control resource allocation" (P48, pp. 140–142).
- **KeyKOS and EROS use banks.** Space banks allocate disk and memory from a master bank, and meters convey the right to run for a time (P53, p. 6); EROS calls its space bank "uniquely as far as we know, user-level storage allocation" (P77, pp. 179, 183).
- **Multicore designs.** Barrelfish manages virtual memory at user level through capabilities and judges its scheme unnecessarily complex (P8, p. 10); fos allocates physical memory through a fleet (P102, p. 6).
- **Comparison.** All agree allocation can leave the kernel; they differ on whether the root is one object (KeyKOS, EROS) or capabilities to raw memory (seL4), and only Barrelfish reports regretting its design (C18).
