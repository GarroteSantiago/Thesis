# C25: Transparent interposition

## Definition
Placing a component (monitor, filter, buffer, proxy) between two communicating parties without changing either. Merges "transparent interposition", "access indirection / forwarding objects", "shadow endpoint", "clans and chiefs" (as redirection), "interposition (wrappers)", "lightweight protection domain (sandboxing)", "shadow driver", "paravirtualization", "encapsulation" and "invisible pointer / forwarding".

## First found in
P45

## What the papers say, compared
- **On messages, from a uniform interface.** In EROS "All capabilities take the same arguments at the trap interface", so a filter process or the kernel's indirector "can be transparently interposed in front of most objects"; a trivial invocation costs 1.6 µs against 0.7 µs for Linux getppid, and "function was favored over performance" (P77, pp. 174, 180). In KeyKOS an intervening domain can add message buffering transparently, and keepers run unmodified BSD binaries; queue domains impose "considerable context switch overhead" (pipe at 0.56 of Mach 2.5), and routing every trap to the keeper "severely penalizes all trivial system calls" (P53, pp. 7, 9–10, 12, 14, 16).
- **On messages, inserted by the system.** Helios inserts shadow endpoints on every remote channel "while preserving the original Singularity channel programming interface", and a process can be moved by editing its manifest "without any changes to the program binary"; the cost is the remote message's latency (P45, pp. 2, 6–7, 10). The M-Machine's trap handlers let "a variety of coherence policies and protocols" be placed under unmodified programs (P66, p. 6).
- **On messages, abandoned.** L4's kernel redirection to clan chiefs added two messages per round trip and was dropped; a more general IPC redirection "failed to gain traction" (P48, p. 139).
- **Not on messages: per-interface wrappers.** Nooks wraps each kernel–driver call in "a wrapper that checks the parameters for validity", catching 99% of fatal and 55% of non-fatal driver errors with 455 hand-written wrappers; drivers in paravirtualized Linux VMs on L4 cost 3–8% but need the guest kernel changed (P49, pp. 45–47). The Lisp Machine wraps function definitions with trace and advise and redirects references with invisible pointers (P73, pp. 153, 174–175).
- **Comparison.** Where every interaction is a uniform message (EROS, KeyKOS, Helios), interposition needs no per-interface code and its cost is one extra hop; where it is not (Nooks), it needs a wrapper per interface. L4 is the counter-case: a message kernel that found kernel-level redirection too costly.
