# C44: Messages built on shared memory

## Definition
Message passing implemented over shared or coherent memory. Merges "URPC", "one-sided put and get" and the "Message Passing Buffer" as a message transport.

## First found in
P8

## What the papers say, compared
- **On coherent memory, at kernel level.** Barrelfish's URPC is a shared-memory, cache-line, point-to-point channel received by polling, tuned to the coherence protocol at two interconnect round trips per message, and costs 450 cycles against 424 for L4 IPC (P8, pp. 9–10). Helios carries remote messages over shared FIFOs, at 11–128 µs by size (P45, pp. 4, 6–7, 10). fos may use shared memory as its transport (P102, pp. 5, 8).
- **On non-coherent on-chip memory.** The SCC's messages are a software protocol of one-sided put and get over 16 KB per-tile buffers; messages under 16 KB are 15 times faster than through DDR3 (P21, pp. 173–177).
- **Inside one address space.** The 432's call message is an object in shared memory (P10, pp. 297, 306–307); Lisp Machine processes pass messages as lists or arrays in shared objects (P73, p. 429); Go's channels live in a language that also shares memory (P9, pp. 2–3).
- **What is lost.** Freedom from data races, when references pass through channels (P9, p. 9); encapsulation, unless a language or capabilities enforce it (P45, P10), and the Lisp Machine deliberately does not (P73, p. 282).
- **Comparison.** On current coherent hardware messages on shared memory cost about as much as kernel IPC (P8); which properties survive depends on enforcement above the memory, not on the memory.
