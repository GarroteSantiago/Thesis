# C8: Message buffering, queues and flow control

## Definition
Where messages wait between send and receipt, and what happens when buffers fill. Merges "return-to-sender flow control / throttling", "congestion as governor (no send queue)", "receive mailbox", "message port and carrier", "IPC endpoint", "message class (network)", "message priorities" and "parallelism control".

## First found in
P21

## What the papers say, compared
- **Kernels avoid buffering.** L4's synchronous IPC avoids kernel buffering; endpoints hold queues of waiting senders, not messages (P48, pp. 136–138). KeyKOS has no kernel buffering; a buffering domain can be placed in the path when needed (P53, p. 7). Minix 3 copies messages only when both sides are ready (P49, p. 48).
- **Machines buffer in hardware and push back.** The MDP has two hardware priority queues and a queue-overflow fault (P65, pp. 2, 10–11); the 1987 design has no send queue, so network congestion blocks the sending object (P69, p. 191). The M-Machine returns unconsumed messages to a buffer reserved at the sender, and SEND stalls when none is reserved (P66, p. 7); the J-Machine's evaluators propose the same "return-to-sender" scheme (P65, p. 11). The SCC's network uses two message classes and reserved virtual channels to keep routing free of deadlock (P21, pp. 175–176).
- **Overflow becomes a rule for programs.** On the J-Machine, Concurrent Smalltalk methods may not loop without a message send, so queues do not overflow (P70, p. 12, footnote), and a switch to sequential evaluation above a queue threshold was explored (P70, pp. 121–124).
- **Operating systems leave it to the sender or to tuning.** In fos a send to a full mailbox returns an error (P102, pp. 6, 8). Barrelfish tests with a 16-message queue, does not state full-queue behaviour, and names "extreme sensitivity to message queue lengths" as a limit (P8, pp. 10, 17).
- **The 432 queues at ports.** Messages are queued to a port object by a carrier (P72, pp. 162, 171).
- **Comparison.** No two designs read handle a full buffer the same way, and only the J-Machine papers report the effect on programs.
